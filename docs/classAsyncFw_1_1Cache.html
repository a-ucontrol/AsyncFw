Detailed Description

template<typename T>
class AsyncFw::Cache< T >

Example:

thread-safe cache wrapper that automatically triggers an update signal when the value expires.

Implements the Stale-While-Revalidate pattern. When the TTL expires, the first caller atomically claims the update slot on expire_ (CAS in acquire(), exchange in refresh()) and dispatches the user callback asynchronously through thread_->invoke(). Subsequent readers during the update phase instantly receive the stale value without blocking on the updater. Readers do not serialize against each other: value_ is guarded by a shared_mutex while expire_ is an atomic lifecycle flag.

TThe type of the cached data object.

template<typename T>
template<Mode::Lock M = Mode::Lock::Exclusive>
SharedLockData< T &, M > AsyncFw::Cache< T >::acquire ( )
inline

Acquires locked access to the cached value.

The locking discipline is selected by the M template parameter: Mode::Lock::Exclusive (default) yields a mutable reference for the updater, Mode::Lock::Shared yields a const reference for readers. If the TTL has expired, the first caller atomically claims the update slot and dispatches the update callback asynchronously on thread_ before the lock is taken.

Template Parameters
MThe locking discipline. Defaults to Mode::Lock::Exclusive.
Returns
A SharedLockData bundling the reference to the data and its active lock.
Note
When M == Mode::Lock::Exclusive, the caller is the updater: it must mutate value_ via the returned SharedLockData and call touch() before that object goes out of scope. When M == Mode::Lock::Shared, the caller is a plain reader and must not call touch().

◆ refresh()

template<typename T>
void AsyncFw::Cache< T >::refresh ( )
inline

Forces a cache invalidation and schedules an asynchronous refresh.

Atomically exchanges expire_ to 0 and dispatches the update callback only if the previous value was non-zero. This guarantees a single winner among concurrent refresh calls and callers arriving while an update is already in flight. Does not require the mutex: expire_ is atomic and refresh does not touch value_. Safe to call from any thread.

Note
Unlike acquire(), refresh() ignores the current TTL and always invalidates: even fresh data is discarded and re-fetched.

Note
MUST be called by the update handler before it releases the lock acquired via acquire(). Skipping it leaves expire_ == 0 forever and the cache stops refreshing. Safe to call while holding the exclusive lock returned from acquire(): expire_ is atomic and value_ is not touched.
